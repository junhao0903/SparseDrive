# Quick Start

### Set up a new virtual environment
```bash
conda create -n sparsedrive python=3.8 -y
conda activate sparsedrive
```

### Install dependency packpages
```bash
sparsedrive_path="path/to/sparsedrive"
cd ${sparsedrive_path}
pip3 install --upgrade pip
pip3 install torch==1.13.0+cu116 torchvision==0.14.0+cu116 torchaudio==0.13.0 --extra-index-url https://download.pytorch.org/whl/cu116
pip3 install -r requirement.txt
```

### Compile the deformable_aggregation CUDA op
```bash
cd projects/mmdet3d_plugin/ops
python3 setup.py develop
cd ../../../
```

### Prepare the data
Download the [NuScenes dataset](https://www.nuscenes.org/nuscenes#download) and CAN bus expansion, put CAN bus expansion in /path/to/nuscenes, create symbolic links.
```bash
cd ${sparsedrive_path}
mkdir data
ln -s path/to/nuscenes ./data/nuscenes
```

Pack the meta-information and labels of the dataset, and generate the required pkl files to data/infos. Note that we also generate map_annos in data_converter, with a roi_size of (30, 60) as default, if you want a different range, you can modify roi_size in tools/data_converter/nuscenes_converter.py.
```bash
sh scripts/create_data.sh
```

### BEV coordinate convention used by detection / map GT

When reading `gt_bboxes_3d`, `map_annos`, `gt_map_pts`, or the default BEV visualization:

- the first coordinate is **x**
- the second coordinate is **y**
- **yaw = 0** means the box heading is aligned with the **positive y-axis**

Practical interpretation for the default BEV plots in this repo:

- **x+** is drawn to the **right** on the canvas
- **y+** is drawn **upward** on the canvas

This means the default `roi_size = (30, 60)` should be read as:

- **x-span = 30 m**
- **y-span = 60 m**

Important note: this is the repo's BEV/vector convention for detection and map GT. Do not confuse it with image pixel coordinates or with other project-specific trajectory conventions.

### Occ3D source convention vs Polygon OCC working convention

- **Raw Occ3D source semantics** should be read in the original Occ3D / nuScenes-style source frame before Polygon OCC conversion.
- **Current Polygon OCC sidecars in this workspace** are intended to be used in the same working BEV convention as detection/map visualization:
  - first coordinate = `x`
  - second coordinate = `y`
  - `x+` is drawn to the **right** on the canvas
  - `y+` is drawn **upward** on the canvas

So when reading `polygon_occ_ann_file`, `polygon_occ_geoms`, `gt_polygon_occ_pts`, or the custom Polygon OCC PKL visualizers in this workspace, interpret them with the same plotting direction used for detection/map unless a script explicitly states otherwise.

### Generate anchors by K-means
Gnerated anchors are saved to data/kmeans and can be visualized in vis/kmeans.
```bash
sh scripts/kmeans.sh
```

### Polygon OCC current workspace baseline

If you are using the custom Polygon OCC workflow in this workspace, the active
baseline is currently:

- `polygon_occ_num_sample = 20`
- Polygon OCC anchor file: `data/kmeans/kmeans_polygon_occ_100_20.npy`
- Polygon OCC sidecars:
  - `data/polygon_occ_infos/polygon_occ_train.pkl`
  - `data/polygon_occ_infos/polygon_occ_val.pkl`

These files are generated by:

```bash
bash scripts/create_polygon_occ_data.sh --keep-work
```


### Download pre-trained weights
Download the required backbone [pre-trained weights](https://download.pytorch.org/models/resnet50-19c8e357.pth).
```bash
mkdir ckpt
wget https://download.pytorch.org/models/resnet50-19c8e357.pth -O ckpt/resnet50-19c8e357.pth
```
